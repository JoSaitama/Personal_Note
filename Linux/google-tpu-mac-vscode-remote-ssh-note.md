## 1. Configuration placeholders

This document uses the placeholders below. Replace them with values from your own environment before running commands or editing configuration files.

| Placeholder | Meaning | How to find it |
|---|---|---|
| `<PROJECT_ID>` | Google Cloud project ID | `gcloud projects list` |
| `<TPU_NAME>` | TPU VM name | `gcloud compute tpus tpu-vm list` |
| `<TPU_ZONE>` | Zone containing the TPU VM | Cloud Console or the TPU VM list |
| `<TPU_SSH_ALIAS>` | Custom local SSH alias | Choose one, such as `my-tpu-vm` |
| `<REMOTE_USER>` | Remote TPU VM username | Output from `gcloud ... ssh --dry-run` |
| `<TPU_EXTERNAL_IP>` | External IP address of the TPU VM | Target IP in the `--dry-run` output |
| `<HOST_KEY_ALIAS>` | SSH host identifier generated by Google | `HostKeyAlias` in the `--dry-run` output |
| `<LOCAL_KEY_PATH>` | Path to the SSH private key on the Mac | Argument following `-i` in the `--dry-run` output |
| `<LOCAL_KNOWN_HOSTS_PATH>` | Google-specific known-hosts file | `UserKnownHostsFile` in the `--dry-run` output |
| `<REMOTE_PROJECT_PATH>` | Project directory on the TPU VM | Use the actual remote directory |
| `<VENV_NAME>` | Python virtual environment name | Use the actual environment name |

[*Blue italic text indicates a value or choice that must be checked and adapted for your environment.*](#1-configuration-placeholders)

### Optional: define variables in the current macOS terminal

To reduce repeated typing, define temporary variables in the local terminal:

[*Replace the placeholder on the right side of each assignment. These variables remain available only in the current shell session.*](#1-configuration-placeholders)

```bash
export PROJECT_ID="<PROJECT_ID>"
export TPU_NAME="<TPU_NAME>"
export TPU_ZONE="<TPU_ZONE>"
export TPU_SSH_ALIAS="<TPU_SSH_ALIAS>"
```

## 2. Install the Google Cloud CLI

Run all commands in this section in a **local macOS terminal**, not on the TPU VM.

Skip this section if `gcloud version` already works.

```bash
brew update
brew install --cask gcloud-cli
gcloud version
```

If Homebrew is not installed, follow the instructions on the [official Homebrew website](https://brew.sh/).

## 3. Sign in and configure Google Cloud

Sign in to a Google account:

```bash
gcloud auth login
gcloud auth list
```

[*Select a Google account that has access to the target TPU project.*](#1-configuration-placeholders)

Set the default project and zone:

```bash
gcloud config set project "${PROJECT_ID}"
gcloud config set compute/zone "${TPU_ZONE}"
gcloud config list
```

If you did not define the temporary variables above, enter the values directly:

```bash
gcloud config set project "<PROJECT_ID>"
gcloud config set compute/zone "<TPU_ZONE>"
```

## 4. Check the TPU VM and test the connection

List TPU VMs in the specified project and zone:

```bash
gcloud compute tpus tpu-vm list \
  --project="${PROJECT_ID}" \
  --zone="${TPU_ZONE}"
```

Test the connection through the Google Cloud CLI:

```bash
gcloud compute tpus tpu-vm ssh "${TPU_NAME}" \
  --project="${PROJECT_ID}" \
  --zone="${TPU_ZONE}"
```

After connecting, verify the remote environment:

```bash
hostname
whoami
pwd
```

Exit the remote server:

```bash
exit
```

> Configure regular SSH and VS Code Remote-SSH only after `gcloud ... ssh` works successfully.

## 5. Retrieve the raw SSH parameters

Run this command in the local macOS terminal:

```bash
gcloud compute tpus tpu-vm ssh "${TPU_NAME}" \
  --project="${PROJECT_ID}" \
  --zone="${TPU_ZONE}" \
  --dry-run
```

The output usually resembles this sanitized example:

```text
/usr/bin/ssh -t \
  -i /Users/<LOCAL_MAC_USER>/.ssh/<PRIVATE_KEY_FILE> \
  -o CheckHostIP=no \
  -o HashKnownHosts=no \
  -o HostKeyAlias=<HOST_KEY_ALIAS> \
  -o IdentitiesOnly=yes \
  -o StrictHostKeyChecking=no \
  -o UserKnownHostsFile=/Users/<LOCAL_MAC_USER>/.ssh/<GOOGLE_KNOWN_HOSTS_FILE> \
  <REMOTE_USER>@<TPU_EXTERNAL_IP>
```

Record the following values:

| Value in the SSH output | SSH configuration field |
|---|---|
| Path following `-i` | `IdentityFile` |
| Username in `<REMOTE_USER>@...` | `User` |
| IP address following `@` | `HostName` |
| Value following `HostKeyAlias=` | `HostKeyAlias` |
| Value following `UserKnownHostsFile=` | `UserKnownHostsFile` |

[*Run `--dry-run` again whenever the TPU is recreated, restarted, or assigned a new network address. Do not reuse stale values from old notes.*](#1-configuration-placeholders)

## 6. Create the macOS SSH configuration

Prepare the local SSH directory and configuration file:

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh
touch ~/.ssh/config
chmod 600 ~/.ssh/config
```

Open the configuration file in VS Code:

```bash
code ~/.ssh/config
```

If the `code` command is unavailable, use the built-in macOS text editor:

```bash
open -e ~/.ssh/config
```

Alternatively, press `Command + Shift + P` in VS Code and run:

```text
Remote-SSH: Open SSH Configuration File
```

Then select the local `~/.ssh/config` file.

### SSH configuration template

Add the following entry to `~/.ssh/config`:

[*Replace every angle-bracket placeholder with the latest value from `--dry-run`. The `Host` value is only a local alias and may be named freely.*](#1-configuration-placeholders)

```sshconfig
Host <TPU_SSH_ALIAS>
    HostName <TPU_EXTERNAL_IP>
    User <REMOTE_USER>
    IdentityFile <LOCAL_KEY_PATH>
    IdentitiesOnly yes

    CheckHostIP no
    HashKnownHosts no
    HostKeyAlias <HOST_KEY_ALIAS>
    StrictHostKeyChecking no
    UserKnownHostsFile <LOCAL_KNOWN_HOSTS_PATH>

    ServerAliveInterval 30
    ServerAliveCountMax 6
    TCPKeepAlive yes
```

The following example uses documentation-only values:

```sshconfig
Host my-tpu-vm
    HostName 203.0.113.10
    User remote_user
    IdentityFile ~/.ssh/google_cloud_private_key
    IdentitiesOnly yes

    CheckHostIP no
    HashKnownHosts no
    HostKeyAlias tpu.example-host-key-alias
    StrictHostKeyChecking no
    UserKnownHostsFile ~/.ssh/google_cloud_known_hosts

    ServerAliveInterval 30
    ServerAliveCountMax 6
    TCPKeepAlive yes
```

> `203.0.113.10` belongs to an IP range reserved for documentation and is not a real server address.

Important notes:

- Do not add `ssh -t` or `-t` from the raw command to the SSH configuration.
- `User` must be the remote username shown by `--dry-run`, not the local macOS username.
- `IdentityFile` points to a private key on the Mac, not a file on the TPU VM.
- Never copy private-key contents into a note or commit them to GitHub.
- If `gcloud ... ssh` already works, manually editing `~/.ssh/authorized_keys` on the TPU VM is usually unnecessary.

## 7. Test the SSH alias

Run this command in the local macOS terminal:

```bash
ssh <TPU_SSH_ALIAS>
```

If the variable was defined earlier, you may instead run:

```bash
ssh "${TPU_SSH_ALIAS}"
```

Verify the remote environment after connecting:

```bash
whoami
hostname
pwd
```

Exit the server:

```bash
exit
```

> If `ssh <TPU_SSH_ALIAS>` does not work, troubleshoot it before opening VS Code. VS Code Remote-SSH uses the same SSH configuration.

## 8. Install and use VS Code Remote-SSH

### 8.1 Install the extension

Search for and install the following extension in VS Code:

```text
Remote - SSH
```

The publisher should be Microsoft, and the extension ID is:

```text
ms-vscode-remote.remote-ssh
```

You may also install it from the local macOS terminal:

```bash
code --install-extension ms-vscode-remote.remote-ssh
```

### 8.2 Connect to the TPU VM

1. Press `Command + Shift + P` in VS Code.
2. Select `Remote-SSH: Connect to Host...`.
3. Select `<TPU_SSH_ALIAS>`.
4. Select `Linux` if VS Code asks for the remote operating system.
5. Wait for VS Code to install VS Code Server on the remote host.

After a successful connection, the lower-left corner of VS Code should display something similar to:

```text
SSH: <TPU_SSH_ALIAS>
```

Select `File → Open Folder` and open the remote project directory:

```text
<REMOTE_PROJECT_PATH>
```

For example, use a generic structure such as:

```text
/home/<REMOTE_USER>/projects/<PROJECT_DIRECTORY>
```

[*Remote usernames, project names, and paths are also sensitive environment details. Keep using placeholders in public notes.*](#1-configuration-placeholders)

## 9. Configure the remote Python environment

After connecting to the TPU VM, select `Terminal → New Terminal` in VS Code.

Confirm that the terminal is running on the remote server:

```bash
hostname
whoami
pwd
```

Check common virtual-environment locations:

```bash
ls -la ~/.venvs 2>/dev/null
conda env list 2>/dev/null
```

For a `venv` environment, activation usually looks like this:

```bash
source "/home/<REMOTE_USER>/.venvs/<VENV_NAME>/bin/activate"
```

Check the active Python installation:

```bash
which python
python --version
pip --version
```

### 9.1 Select the remote interpreter

1. Install the Microsoft Python extension in the remote VS Code window.
2. Press `Command + Shift + P`.
3. Run `Python: Select Interpreter`.
4. Select or manually enter:

```text
/home/<REMOTE_USER>/.venvs/<VENV_NAME>/bin/python
```

### 9.2 Add project-level VS Code settings

Create `.vscode/settings.json` in the remote project if needed:

```json
{
    "python.defaultInterpreterPath": "/home/<REMOTE_USER>/.venvs/<VENV_NAME>/bin/python",
    "python.terminal.activateEnvironment": true
}
```

`remote.SSH.connectTimeout` is a local SSH setting. To increase the timeout, add this to the **local VS Code user settings on the Mac**:

```json
{
    "remote.SSH.connectTimeout": 60
}
```

## 10. Handle a TPU restart or IP address change

If the connection previously worked but now times out or cannot be established, run:

```bash
gcloud compute tpus tpu-vm ssh "<TPU_NAME>" \
  --project="<PROJECT_ID>" \
  --zone="<TPU_ZONE>" \
  --dry-run
```

Compare the new output with `~/.ssh/config`. Update these fields first:

```sshconfig
HostName <NEW_TPU_EXTERNAL_IP>
HostKeyAlias <NEW_HOST_KEY_ALIAS>
```

Also check these fields when necessary:

```sshconfig
User <REMOTE_USER>
IdentityFile <LOCAL_KEY_PATH>
UserKnownHostsFile <LOCAL_KNOWN_HOSTS_PATH>
```

Test regular SSH again:

```bash
ssh <TPU_SSH_ALIAS>
```

Reconnect through VS Code Remote-SSH only after regular SSH works.

## 11. Troubleshooting

### 11.1 `Permission denied (publickey)`

First confirm that the native Google Cloud command still works:

```bash
gcloud compute tpus tpu-vm ssh "<TPU_NAME>" \
  --project="<PROJECT_ID>" \
  --zone="<TPU_ZONE>"
```

Check the local key and configuration permissions:

```bash
ls -l <LOCAL_KEY_PATH>
ls -l <LOCAL_KEY_PATH>.pub

chmod 700 ~/.ssh
chmod 600 <LOCAL_KEY_PATH>
chmod 644 <LOCAL_KEY_PATH>.pub
chmod 600 ~/.ssh/config
```

Inspect the final SSH configuration after all rules are resolved:

```bash
ssh -G <TPU_SSH_ALIAS> | grep -E '^(hostname|user|identityfile|hostkeyalias|userknownhostsfile) '
```

Enable verbose diagnostics:

```bash
ssh -vvv <TPU_SSH_ALIAS>
```

Confirm that the debug output shows the expected `IdentityFile` being offered.

### 11.2 `Connection timed out`

Check the TPU VM status:

```bash
gcloud compute tpus tpu-vm describe "<TPU_NAME>" \
  --project="<PROJECT_ID>" \
  --zone="<TPU_ZONE>"
```

Test the native Google Cloud connection again:

```bash
gcloud compute tpus tpu-vm ssh "<TPU_NAME>" \
  --project="<PROJECT_ID>" \
  --zone="<TPU_ZONE>"
```

If the native command works but the SSH alias fails, recheck `HostName`, `User`, `IdentityFile`, and `HostKeyAlias`.

### 11.3 VS Code is stuck while installing the remote server

Open the following panel in VS Code:

```text
View → Output → Remote - SSH
```

Review the specific error, then run:

```text
Remote-SSH: Kill VS Code Server on Host...
```

Select `<TPU_SSH_ALIAS>` and reconnect.

If the remote home directory may be low on space, check it on the TPU VM:

```bash
df -h ~
du -sh ~/.vscode-server 2>/dev/null
```

### 11.4 `REMOTE HOST IDENTIFICATION HAS CHANGED`

Run `--dry-run` again to verify the current TPU IP address and `HostKeyAlias`:

```bash
gcloud compute tpus tpu-vm ssh "<TPU_NAME>" \
  --project="<PROJECT_ID>" \
  --zone="<TPU_ZONE>" \
  --dry-run
```

Update `HostName` and `HostKeyAlias` for the relevant host in `~/.ssh/config`. Do not clear the entire `~/.ssh/known_hosts` file, because doing so removes trusted-host records for unrelated servers.

If a separate Google known-hosts file is configured, remove only the exact alias from the exact file specified by `--dry-run`:

```bash
ssh-keygen -R "<HOST_KEY_ALIAS>" -f "<LOCAL_KNOWN_HOSTS_PATH>"
```

[*Before removing an old host record, confirm that both the path and `HostKeyAlias` exactly match the current TPU configuration.*](#1-configuration-placeholders)

### 11.5 `code: command not found`

Press `Command + Shift + P` in the local VS Code application and run:

```text
Shell Command: Install 'code' command in PATH
```

Open a new terminal and verify the installation:

```bash
code --version
```

## 12. Daily workflow

For routine use:

1. Confirm that the TPU VM is running.
2. Open VS Code.
3. Press `Command + Shift + P`.
4. Select `Remote-SSH: Connect to Host...`.
5. Select `<TPU_SSH_ALIAS>`.
6. Open the remote project directory.
7. Confirm the Python interpreter and virtual environment.

Keep these two diagnostic commands available:

```bash
# Verify the native Google Cloud connection
gcloud compute tpus tpu-vm ssh "<TPU_NAME>" \
  --project="<PROJECT_ID>" \
  --zone="<TPU_ZONE>"
```

```bash
# Verify the regular SSH connection used by VS Code
ssh <TPU_SSH_ALIAS>
```

If the second command connects successfully, VS Code Remote-SSH will usually connect as well.

## 13. Sanitization checks before publishing to GitHub

### 13.1 Files that must never be committed

Add the following patterns to the repository's `.gitignore`:

```gitignore
# SSH private/public keys and host records
*.pem
*.key
*.ppk
id_rsa
id_rsa.pub
id_ed25519
id_ed25519.pub
google_compute_engine
google_compute_engine.pub
known_hosts
google_*_known_hosts

# Google Cloud local credentials and configuration
.config/gcloud/
application_default_credentials.json

# Local environment files
.env
.env.*
```

> A public key is less sensitive than a private key, but a personal notes repository usually has no reason to include either one.

### 13.2 Search for sensitive patterns before committing

Run this command from the root of the notes repository:

```bash
rg -n --hidden \
  -g '!\.git/**' \
  -e '([0-9]{1,3}\.){3}[0-9]{1,3}' \
  -e 'HostKeyAlias' \
  -e '@.*\.(com|edu|org)' \
  -e '/Users/[^/]+' \
  -e '/home/[^/]+' \
  -e 'BEGIN (OPENSSH|RSA|EC|DSA) PRIVATE KEY' \
  .
```

This command may match documentation examples or placeholders. Review every result manually.

Inspect the content staged for Git:

```bash
git status
git diff --cached
```

### 13.3 Sanitization checklist

- [ ] The project ID has been replaced with `<PROJECT_ID>`.
- [ ] The TPU name has been replaced with `<TPU_NAME>`.
- [ ] The zone or region has been replaced with `<TPU_ZONE>`.
- [ ] The remote username or email-style account has been replaced with `<REMOTE_USER>`.
- [ ] The external IP address has been replaced with `<TPU_EXTERNAL_IP>`.
- [ ] The local macOS username and absolute paths have been replaced.
- [ ] The remote home directory and project paths have been replaced.
- [ ] The real `HostKeyAlias` has been replaced with `<HOST_KEY_ALIAS>`.
- [ ] No private key, public key, or key contents are included.
- [ ] No Google Cloud credentials, tokens, or JSON keys are included.
- [ ] Terminal screenshots and logs contain no account names, IP addresses, project names, or key information.
